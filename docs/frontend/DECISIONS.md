# ClinSync frontend — decision log

Plan §0.2 rule 10: *"Image-vs-landing-page conflicts: the reference image wins
for layout, component structure, shapes, and the tokens in §7. Landing-page
fonts/colours may be adopted only if the landing page actually uses them and
they are visually compatible; log every deviation here."*

Every entry says what was decided, why, and what it costs.

---

## FD-01 — Icon family: `lucide_icons_flutter`, not `lucide_icons`

**Decided:** depend on `lucide_icons_flutter ^3.1.21`.

**Why:** `lucide_icons` (the sibling package) declares its icons as subclasses
of `final class IconData`. On Flutter 3.47 the `dart2js` compiler rejects
extending `IconData`, so `flutter build web` fails with a compile error on that
package. `lucide_icons_flutter` returns plain `IconData` values.

**Cost:** none. Same glyphs, same licence.

## FD-02 — Serif = Cormorant Garamond, bundled as static TTFs

**Decided:** display serif is Cormorant Garamond, instanced from the variable
font to static 400/500/600 TTFs in `assets/fonts/` and declared in
`pubspec.yaml`.

**Why:** §7.2 says to use the landing page's serif if it has one. The landing
page (`index.html`) loads Cormorant Garamond, and it is visually compatible with
the reference headline — high-contrast transitional serif, editorial, calm.
Bundling static instances means **no runtime font download**, which §7.2
requires explicitly and which also makes an offline demo work.

**Cost:** +3 TTFs (~180 KB) in the repo. Weights outside 400/500/600 are not
available and must be simulated.

## FD-03 — State management: Riverpod; routing: `go_router`

**Decided:** `flutter_riverpod ^2.5.1` for state, `go_router ^14.2.7` for
routing with a single `ShellRoute`.

**Why:** the app is 20 screens with deep links (`/patients/<id>/brief`,
`/investigations/<id>/trend`) that must survive a page refresh on web and a cold
start on mobile. `go_router` gives named routes, path parameters and a redirect
guard in one place; Riverpod gives testable, overridable providers, which is
what makes the widget tests in `test/components_test.dart` possible without a
backend.

**Layout decision:** screens never touch `ApiClient`. The chain is
`widget → provider (AsyncSlice<T>) → repository → ApiClient`, per §0.2's layer
rule.

## FD-04 — Ambient video is skipped on web

**Decided:** `AmbientLayer` renders the poster still on web and only mounts
`VideoPlayerController` on Android/iOS/macOS (`!kIsWeb`).

**Why:** on web `video_player` renders through a **platform view**, and a
platform view always composites *above* the Flutter canvas regardless of widget
order. The Home hero's search pill deliberately overhangs the hero's bottom edge
(reference §6.1 el. 6); with a platform-view video the video would paint over
the pill. The video is also confined to `videoFraction` (0.62) of the layer
height so it cannot reach content directly beneath it.

**Cost:** the web demo shows a still frame instead of motion. The still is a
frame of the *same* loop (FD-05), so the poster→video transition is invisible
on mobile.

## FD-05 — Ambient stills are extracted from `lightNoWatermark.mp4`, not invented

**Decided:** every file in `assets/images/ambient-*.jpg` is generated by
`tools/extract_ambient_stills.py`, which pulls specific frames out of the
landing page's own loops (`lightNoWatermark.mp4`, `assets/video/hero-light.mp4`,
`assets/video/ribbon-light.mp4`) and maps them through a **duotone ramp** from
`primaryDark` to `bgCanvas`.

**Why:** §6.5(a) requires patient-card and thumbnail imagery to be "stills
extracted from `lightNoWatermark` … tinted to the sage palette", and forbids
invented or patient-photograph imagery. The source loops are bright, near-white
chrome renders, so a saturation tweak does nothing (they are almost achromatic);
a duotone ramp lands the artwork inside the palette *by construction* and
reproduces the reference's "pale and desaturated, fading into the background"
quality (§6.1 el. 5).

**Cost:** regenerating requires `ffmpeg` + Pillow. The script is deterministic
(frame indices are constants), so the checked-in files are reproducible.

**Rejected:** hand-painted/AI-generated misty landscape artwork. It looked good
but it is invented imagery, which §6.5 does not allow.

## FD-06 — Home hero wash raised from 0.30 to 0.52

**Decided:** `AmbientLayer(washOpacity: 0.52, videoOpacity: 0.55)` for the Home
hero.

**Why:** the plan's 0.30 wash was tuned for a painterly background. The real
ambient loop is a high-contrast chrome render on near-white, so at 0.30 the
ribbon competed with the headline ("Clinically" sat on chrome). 0.52 keeps the
motion legible as depth while the headline stays the focal point, and keeps the
subtitle at AA contrast.

## FD-07 — Serif figures forced to lining + tabular

**Decided:** every serif style sets `fontFeatures: [liningFigures(),
tabularFigures()]`.

**Why:** Cormorant Garamond ships **oldstyle figures** by default, where `0` sits
at x-height. The captured Brief screenshot rendered the screen title as
"6o-Second Brief" — in a clinical product a dose or a year could be misread the
same way. Lining figures keep digits full-height; tabular figures stop values
from shifting width as they update (the trend counter animates).

**Cost:** the serif loses a little of its bookish character in numeric strings.
That is the right trade for this domain.

## FD-08 — Colours sampled from `appTheme.jpg`, three values differ from §7.1

**Decided:** use the sampled values, not the §7.1 estimates, for
`bgBackdrop #D3DECE`, `bgCanvas #F6F6F4`, `primary #527A55`, plus a new
`primaryMuted #6A866D` sampled from the boarding-pass band. `textPrimary` was
softened from the sampled `#0A0A0A` to `#141814`.

**Why:** §7 explicitly authorises sampling, and the structure ("white on sage,
one green, big radii, soft shadow") is unchanged — only the exact hex values
moved. Full sampling log and rationale per token in `DESIGN_TOKENS.md`.

**Cost:** three token values differ from the plan's table. All are logged here
and in `DESIGN_TOKENS.md` as required.

## FD-09 — `Demo data` tag comes from fixture provenance, not `meta.source`

**Decided:** `ApiMeta.isFallback` still reads `meta.source == "fallback"`, but
repositories mark a payload as demo data when they actually served a bundled
fixture from `assets/demo/`.

**Why:** the backend never emits `meta.source == "fallback"` — it emits `db`,
`llm`, `system`, `stt` only (verified against live responses, see
`API_MISMATCHES.md` M-01). Keying the tag purely off that field would make the
§6.6 rule-8 tag permanently invisible, which is worse than useless during a demo.

## FD-10 — The specialty catalogue is fetched, with a bundled offline mirror

**Decided:** `SpecialtyRepository` reads `GET /specialties` and maps each row to a
`SpecialtyOption` (`{id, name, description}` + glyph). The `Specialty` enum is
no longer the picker — it is only the glyph source and the offline mirror, used
when the endpoint is unreachable.

**Superseded:** an earlier pass in this same work bundled the list outright
because `GET /specialties` was returning HTTP 500. Re-probing the live backend
(`tools/probe_api.py`) showed a correct 200 envelope, so the fetch was restored.

**Why:** the backend owns this list — it is what `POST /brief` validates a
specialty against — so a second hardcoded copy is a drift risk. Fetching means a
specialty added on the backend appears in the picker immediately.

**Cost:** two representations. A specialty the app has no glyph for still renders
(`SpecialtyOption.specialty` is `null` and falls back to a neutral stack glyph)
rather than silently collapsing into General Medicine — the earlier enum-only
version would have done exactly that. Covered by `test/models_test.dart`.

## FD-11 — Medication history is fetched per canonical name

**Decided:** `GET /patients/{id}/medications` is the index; the history for the
reconciliation screen is fetched with `?canonical_name=Metformin`.

**Why:** the medication list payload carries no `group_key`, so there is no way
to ask the backend "give me the full history of the medication the doctor tapped"
without knowing its canonical name — which the list does return. Documented as
M-07.

## FD-12 — No login, profile, or settings-as-a-screen

**Decided:** the app has no auth screens. Connection settings live in the Home
menu sheet.

**Why:** the backend's `deps.get_current_user` is a stub that always returns
`doc_001`; there is no `/auth/*` route family at all. Building a login screen
would imply a security model that does not exist. The base-URL override is a
*developer* control, not a user-facing account screen.

## FD-13 — iOS platform folder generated during this work

**Decided:** `flutter create --platforms=ios .` was run to add the `ios/`
folder; the existing `index.html`, `assets/css/style.css` and `assets/js/main.js`
were verified byte-identical afterwards (md5).

**Why:** the repo had `android/`, `macos/` and `web/` but no `ios/`, while §3
requires camera/mic permissions to be declared on every platform the app targets.
Generating the folder is the only way those declarations can exist. Verified that
`flutter create` touched nothing outside `ios/`.

## FD-14 — Web deep links use the hash strategy

**Decided:** keep Flutter's default hash URL strategy and document it, plus ship
`tools/serve_web.py` with SPA fallback for hosts that serve paths.

**Why:** switching to path URLs means every host serving `build/web` must rewrite
unknown paths to `index.html`, and `http.server` does not. The hash strategy
means `build/web` works on any static host with zero configuration, at the cost
of `/#/patients/<id>`-style URLs.

## FD-15 — Screens hold "no recommendation" language; both conflict sources shown

**Decided:** medication conflicts render source A and source B side by side with
no ordering implied, copy is phrased as a question, and trends are described
without causal language.

**Why:** §6.6 rules 3–5. Enforced by `test/components_test.dart` ("no component
renders directive or causal language", "missing information is phrased as a
question") and by the API error map in `core/networking/error_messages.dart`.

## FD-16 — Tokens are enforced by a test, not by convention

**Decided:** `test/components_test.dart` greps `lib/features/**` and
`lib/shared/**` for raw `Color(0x…)` literals, `fontFamily:` strings and
one-off `TextStyle`s, and fails if any appear outside `core/theme/`.

**Why:** "no raw colours/sizes elsewhere in code" is a plan acceptance criterion
for C06 that is otherwise unenforceable in review. The test turns it into a build
failure.
